# 工程纪律 · 速查清单

> 用法：**强制触发**——产出任何结论前逐项打勾「A 区」，交付前逐项打勾「B 区」，操作过程参考「C 区」（触发点见《决策篇》§三.6、§五.3）。
> 本清单是**防漏闸门**：不加载即等于该闸门不存在。凭记忆默念勾选项无效——实测失败模式正是「自以为记得内容、全程未加载」，必须实际打开本文档逐项打勾。
> 条款的解释与理由见《决策篇》`general-engineering-discipline.md` 与《执行篇》`execution-playbook.md`，本文件只提供勾选项。

## A 区 · 动手前

### A1 意图与需求（《决策篇》§一、§二）

- [ ] 已判定本次属于 A（只查）/ B（只讨论）/ C（动手）哪一类
- [ ] A / B 类下确认本次**没有任何写操作**
- [ ] 判断模糊时已按 A/B 处理，先问再做
- [ ] 需求无歧义；有歧义已一次性问清并给出「选项 + 代价」
- [ ] 多步骤任务已先行复述并获用户确认

### A2 查证质量（《决策篇》§三）

> **本区已常驻，不加载也会生效**：权威内容在 `checklists-core.md`（`alwaysApply: true`）。此处**刻意不重复**，避免两处不同步——修改请只改该文件。产出结论前直接打勾其 §A2。

### A3 风险分级与退路（《决策篇》§四）

- [ ] 已判定本次改动属于 L1 / L2 / **L3**
- [ ] L2：已梳理影响面，明确回滚方式
- [ ] L3：① 退路已就绪（备份 / 快照 / 替代命令）② 已列出「将不可逆地变更什么」③ 已取得显式二次确认
- [ ] 已回答「失败了怎么退」
- [ ] 未使用未经提示的破坏性参数（`--force` / `DROP` / `--hard` / `--delete`）

## B 区 · 交付前

### B1 Definition of Done（《决策篇》§五.3）

> **本区已常驻，不加载也会生效**：权威内容在 `checklists-core.md`（`alwaysApply: true`）。此处**刻意不重复**，避免两处不同步——修改请只改该文件。交付前直接打勾其 §B1。

### B2 改造流程收尾（《决策篇》§五）

- [ ] 每次只交付一项，已报告「改了哪些文件 / 每项改了什么 / 如何验收」
- [ ] 删除或重命名的导出符号已全局搜索确认**零残留**
- [ ] 改动已**回读确认**（工具返回成功 ≠ 内容真的改了）
- [ ] 相关文档 / 进度表已同步更新

### B3 设计与复用自查（《决策篇》§六、§七）

- [ ] 新增的抽象 / 配置项**现在就有调用方**
- [ ] 能用更简单结构实现的，没有多拆
- [ ] 迁移类改造保持了对外接口不变，调用方零改动
- [ ] 已明确列出复用了哪些既有机制（说得出名字）
- [ ] 新代码与既有同类消费方的接法**一致**，没有出现第二种姿势
- [ ] 未夹带修改框架本身的改动
- [ ] 需要改框架时已单独提案，而非顺手改

### B4 外部依赖准入（《决策篇》§七.6）

- [ ] 授权协议兼容
- [ ] 体积与依赖树可接受
- [ ] 维护活跃度足够
- [ ] 无已知高危 CVE
- [ ] 标准库 / 既有依赖无法替代（不可替代性已确认）

### B5 决策留痕（《决策篇》§七.7）

- [ ] 重大选型已记录「为什么选 A 不选 B，放弃了什么」

## C 区 · 执行过程

### C1 命令执行（《执行篇》§二、§三、§四）

- [ ] 长命令**实时回显**，没有把输出 pipe 给 `tail` / `grep` 后再展示
- [ ] 需要过滤时采用「落盘 + 事后查看」两步走，而非管道直连
- [ ] 耗时操作已提前告知预计时长
- [ ] 写操作命令**幂等**，可安全重复执行
- [ ] 失败后先读懂错误信息再改；**未连续重试同一条命令 3 次以上**
- [ ] 同类失败 2 次后已换策略或向用户报告
- [ ] 输出可能含凭据时已脱敏 / 改用不打印凭据的等价命令

### C2 环境安全（《执行篇》§五）

- [ ] 脚本 / 命令指向的环境已明确写为「目标环境 = X」
- [ ] 排查脚本、校验脚本未连接生产数据源
- [ ] 未使用生产凭据跑本地调试

### C3 收尾清理（《执行篇》§一）

- [ ] AI 自行创建的临时脚本已删除，工作区无残留
- [ ] 临时文件使用了 `tmp_` / `temp_` 前缀，可识别
- [ ] 未删除用户或项目既有的任何文件
