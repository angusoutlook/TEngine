# 工程纪律 · 核心勾选项（常驻摘录）

> **为什么单独常驻**：完整清单 `checklists.md` 是按需加载的，实操中出现过「自以为记得内容、全程未实际加载」导致防漏闸门整体失效的情况。本文件只常驻**最关键且最短**的两区，代价约为全文常驻的 1/5。
>
> **本文件是 A2 / B1 的唯一权威来源**。`checklists.md` 中对应小节仅保留指针、不重复内容，避免两处不同步。修改时只改这里。

## A2 查证质量 —— 产出任何结论前逐项打勾

- [ ] 目标范围内文件已**完整读完**（不是只看片段、不是靠搜索结果代替阅读）
- [ ] 阅读范围用**调用链闭包**界定，而非遍历目录；已能说明「读了哪些、其余为何不在范围内」
- [ ] 每条结论都有 `文件:行号` 证据
- [ ] **证据描述的状态 == 结论断言的状态**（论域匹配：不是「另一时刻 / 另一条件下的同名文件」，见《决策篇》§三.3）
- [ ] 组合推演得出的结论已标注「【推断，未验证】」或已追完完整证据链
- [ ] 运行时状态类结论已同时给出**写入方**（谁写、何时写、有无过期）
- [ ] 查不到的项写的是「未找到」，没有用推测补齐

## B1 Definition of Done —— 交付前逐项打勾

- [ ] **构建通过**：相关项目 / 模块编译或类型检查通过（记录了实际命令与结果）
- [ ] **lint 零新增**：`read_lints` 无新引入错误
- [ ] **测试通过**：相关既有测试跑过；无覆盖的改动写明了手工验证步骤与实际结果
- [ ] **diff 已自读**：无夹带、无调试残留、无注释掉的代码
- [ ] 未跑的项已**明确说明**，没有略过不提

## 何时加载完整清单

涉及动手前意图/需求/风险退路（A1、A3）、交付后收尾（B2–B5）、执行过程（C 区）时，加载 `checklists.md`。
